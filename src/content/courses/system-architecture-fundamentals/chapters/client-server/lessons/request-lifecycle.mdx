## 2. The Socket Abstraction

On Linux and Unix-like operating systems, network connections are exposed to programs as **file descriptors**.

A socket pair is uniquely identified by five parameters (the 5-tuple):
- **Source IP Address**
- **Source Port**
- **Destination IP Address**
- **Destination Port**
- **Transport Protocol (TCP/UDP)**

Because a client OS randomly selects an ephemeral source port (e.g., `51234`), a single server listening on port `443` can maintain tens of thousands of concurrent open connections simultaneously!

<InfoCallout type="tip" title="Production Reality">
Servers rarely run out of ports; instead, they run out of <strong>file descriptors</strong> or kernel memory allocated to socket buffers (`rmem` and `wmem`).
</InfoCallout>

## 3. TCP vs UDP: The Core Trade-Off

Software engineers select transport protocols based on whether **guaranteed delivery** or **lowest latency** is the primary requirement.

- **TCP (Transmission Control Protocol)**:
  - Connection-oriented.
  - Guaranteed in-order packet arrival.
  - Automatic congestion control and retransmissions.
  - *Best for*: Financial transactions, REST APIs, HTML documents, file transfers.

- **UDP (User Datagram Protocol)**:
  - Connectionless datagrams.
  - No handshakes; packets are sent into the network without confirmation.
  - Packets may arrive out of order, get duplicated, or drop completely.
  - *Best for*: Live video streaming, online multiplayer games, DNS queries, VoIP.
