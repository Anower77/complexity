2. The 5-Tuple & Kernel Sockets

On Unix and Linux operating systems, every network connection is exposed as a file descriptor backed by a kernel socket. The OS kernel uniquely identifies every TCP socket connection via the 5-tuple:

Because the client port is dynamically allocated from the ephemeral port range (`32768–60999` by default on Linux), a single server listening on port 443 can easily sustain tens of thousands of simultaneous connections as long as each client socket has a distinct source port or IP.

3. TCP Handshake & Connection Overhead

Before a single byte of HTTP payload can be transmitted, the client and server must agree on initial sequence numbers and window sizes via the three-way handshake:

  1. SYN: Client sends an initial sequence number `ISN_c`.
  2. SYN-ACK: Server acknowledges with `ACK = ISN_c + 1` and provides its own `ISN_s`.
  3. ACK: Client acknowledges `ISN_s + 1`. The socket state transitions to `ESTABLISHED`.
WARNING Latency Penalty (1 RTT)
Every new TCP connection adds at least one full Round Trip Time (RTT) of network latency before any application payload can travel. Across transatlantic links (70ms RTT), establishing a fresh connection before each request creates unacceptable user delay. This is why HTTP persistent connections (`Keep-Alive`) and connection pools are mandatory in production.

4. TLS 1.3 Cryptographic Handshake

Under TLS 1.2, cryptographic negotiation required two additional round trips. TLS 1.3 reduced this overhead to a single round trip (1-RTT) by combining cryptographic parameter negotiation into the initial ClientHello message using Diffie-Hellman ephemeral key exchange:

  │                                                   │

5. HTTP/1.1 vs HTTP/2 vs HTTP/3

The application layer protocols evolved specifically to eliminate latency bottlenecks:

  • HTTP/1.1: Sequential pipelining suffered from Head-of-Line (HoL) blocking. If response #1 hung, subsequent responses on that socket were blocked.
  • HTTP/2: Introduced binary framing and bidirectional stream multiplexing over a single shared TCP socket.
  • HTTP/3 (QUIC): Replaced TCP with UDP-based QUIC, eliminating transport-layer Head-of-Line blocking when packets are lost.

7. Key Takeaways & References

  • 5-Tuple Connection Identity: Sockets are bound to protocol, source IP/port, and destination IP/port.
  • Connection Re-use: Handshake overhead makes persistent connections and pool reuse essential for low latency.
  • Stream Multiplexing: HTTP/2 interleaves frames over one socket; HTTP/3 eliminates TCP HoL blocking using UDP.

Canonical RFC Standards

  • RFC 793: Transmission Control Protocol Specification
  • RFC 8446: The Transport Layer Security (TLS) Protocol Version 1.3
